# Positioning. ch47.

Load before any strategic decision. This document is the foundation the other skills build on.

## How to Use

This skill has two modes.

**Grounding mode.** When another skill needs strategic context (brand-voice needs to know the audience, content-strategy needs to know the pillars), load `references/position.md` and use it as the source of truth. Don't reinterpret. Apply directly.

**Thinking mode.** When Jackson is working through a strategic question (should I do X? who is this for? does this fit?), load `references/position.md` and use the frameworks inside to pressure-test the decision. The positioning document contains decision filters for exactly this purpose.

## When to Push Back

The positioning document defines boundaries. If Jackson proposes something that contradicts the positioning (content that serves the wrong audience, a tone that drifts corporate, a project that doesn't generate build material), surface the tension. Don't block. Flag.

Pattern: "That could work, but it's outside the current positioning because [specific reason]. Want to do it anyway, or adjust the positioning?"

## Living Document Protocol

The positioning will evolve. When Jackson makes a strategic decision that updates the positioning (new audience insight, refined thesis, monetization direction), suggest updating `references/position.md` to reflect it. The document should always represent current thinking, not historical thinking.

## Key Principle

ch47 positioning is implicit, not declared. The audience infers it from what gets made. This skill exists to keep the *maker* aligned, not to produce positioning statements for public consumption. If anything from this document ends up in published content verbatim, something went wrong.
